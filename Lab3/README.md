# Lab3 — Маркерные потоки (ОС)

Проект демонстрирует работу с **потоками** и синхронизацией при совместной работе с общим массивом.
В репозитории две реализации одной и той же логики:

- **WinAPI** — потоки + события (`CreateThread`, `CreateEvent`, `WaitForMultipleObjects`) и `CRITICAL_SECTION`.
- **std::thread** — потоки стандартной библиотеки (`std::thread`, `std::mutex`, `std::condition_variable`).

Также в проекте есть **автотесты(bandit)** и **генерация HTML‑отчёта с помощью Allure**

## Инструкции по сборке

> Ниже показан пример для сборки одной версии. Для второй версии делайте то же самое,
> но из папки соответствующей версии (WinAPI или STDThread).


1) Создайте папку `build` и перейдите в неё:

```bat
mkdir build
cd build
```

2) Настройте CMake:

```bat
cmake ..
```

3) Соберите проект:

```bat
cmake --build .
```

>Требования: CMake ≥ 3.15, компилятор C++, установленный Git (для FetchContent/bandit).

## Запуск приложения

Запуск из папки `build`

### STDThread версия
```bat
.\Debug\Lab2_STDThread.exe
```

### WinAPI версия
```bat
.\Debug\Lab2_WinAPI.exe
```

## Тестирование

Запуск тестов:

```bat
.\Debug\tests.exe
```

## Генерация отчета (Allure)

Генерация отчета:

```bat
cmake --build . --target allure_report
```

## Просмотр отчетов

Откройте в браузере: `build\allure-report\index.html`

## Возможности

- Создание массива и работа с ним из нескольких потоков (**marker threads**).
- Управление потоками из главного потока (запуск, ожидание сигналов, остановка выбранного потока).
- Синхронизация доступа к выводу/общим данным (в WinAPI‑версии через `CRITICAL_SECTION` и события).
- Автотесты + генерация HTML‑отчёта Allure.
